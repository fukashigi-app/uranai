# 最終確認画面（特定商取引法 第12条の6）の記録

この文書は、現在の画面遷移と、不足の可能性を記録するものです。**法令に適合していると判断したものではありません。** 適合しているかどうかは、運営者が専門家または消費者庁の資料で確認してください。

## 現在の画面遷移（一般のお客さん）

1. `/s/{店舗コード}`（店舗の QR）で占いを選ぶ。「どれも1回100円です」と表示する。ここでは注文を作るだけで、請求はしない
2. `/payment`（アプリの支払いの画面）
   - 「お申込み内容の確認」（`src/components/public/purchase-summary.tsx`）を、ボタンより上に表示する
     - 表示する内容：購入内容（1回分）、価格（100円・税込、ほかの料金なし）、支払い方法と時期、提供の時期、利用期限（24時間）、再表示（24時間）、申込み期限（30分と時刻）、キャンセル（手続きの完了前なら料金なし）と返金の条件、未成年の方への注意、3つの文書へのリンク
   - 「同意して100円を支払う」ボタンを押すと、Stripe Checkout へ移動する。**この時点ではまだ請求されない**
3. Stripe Checkout（Stripe が提供する画面）で、カード情報などを入力して支払いを確定する。**申込みが確定するのはこの画面**
   - Stripe の画面に表示されるのは、商品名・金額・支払い方法の入力欄など、Stripe が決めた内容。アプリの側からは、提供の時期・利用期限・キャンセルと返金の条件は表示していない
4. `/payment/return` で確定を確かめた後、`/fortune/input` から `/fortune/result` へ進む

## 不足の可能性（未確認）

- 第12条の6 の「最終確認画面」が、申込みを確定する画面（Stripe Checkout）を指すのか、その直前のアプリの画面（`/payment`）で足りるのか
- Stripe Checkout の画面に、分量・支払いの時期・提供の時期・申込みの期間・申込みの撤回や解除に関する事項が表示されないこと。必要であれば、Stripe の設定（カスタムの文言・利用規約への同意の欄など）で補えるか
- `/payment` のボタンの文言「同意して100円を支払う」が、実際には「Stripe の画面へ進む」操作であることの分かりやすさ（`/payment` には「Stripe の決済画面に移動します。決済画面でお支払いの手続きを完了した時点で決済されます」と表示している）

## 確認する人・確認すること

- 運営者：上の3点を、消費者庁の「通信販売の申込み段階における表示についてのガイドライン」または専門家に確認する
- 運営者：Stripe の管理画面で、Checkout に追加できる表示（利用規約への同意・カスタムの文言）を確認する
